# 单输出内容评审规则 v1

适用：后续指定提示词重生成或载体内容保留任务。状态：评审流程已定义，具体任务表、评审人员和实验配置尚未冻结；当前评审数为0。历史开发图仍保留原始标签，不自动补标。

## 生成前固定任务

每个任务应记录 `task_id`、任务轨道、完整提示词、参考/载体SHA256、指定修改、必须保留的内容、允许变化及所有判据。每条判据有唯一ID、明确可见对象和 `required=true/false`。至少一条必须判据；含糊或相互矛盾的要求应在生成前解决。冻结任务文件及哈希之后才启动生成。

| 维度 | 评审问题 | 标注重点 |
|---|---|---|
| 主体 | 图中是否清楚出现指定主体？ | 对象类别、数量或身份分别列项；不能只凭颜色/背景认定主体。 |
| 属性 | 指定属性是否出现在指定对象上？ | 例如红色属于帆船本体还是背景；多属性分开判定。 |
| 动作与关系 | 指定动作及对象间关系是否可见？ | 区分“旁边”“上面”“骑乘”等；遮挡无法确认时标uncertain。 |
| 场景 | 所需环境及背景是否出现？ | 指定湖泊、室内等；主体符合不代表环境符合。 |
| 风格 | 指定表现风格是否有可见依据？ | 摄影、水彩等单列；是否必须由任务预先声明。 |
| 保留内容 | 载体任务要求保留的结构/身份是否仍可辨认？ | 必须提供可查看的载体；不得用共享提示词代替保留证据。 |
| 修改达成 | 指定改变是否真实发生？ | 对照参考或载体逐项确认；像素哈希不同只证明文件不同。 |

## 评审与记录

使用[空白评审CSV](../templates/content_adjudication.csv)，每行对应一个候选、一条判据和一位评审者。`answer`只允许 `yes`、`no`、`uncertain`；不适用的维度应在任务阶段不设为判据，不用空值冒充通过。`visual_evidence`描述可见依据，不能从文件名、生成提示词或检测分数推断画面。若不可访问图片，则记录状态而不评分。

候选先固定字节和SHA256，评估端分配匿名编号并提供内容要求；隐藏方法名、目标水印结果和分数。重生成任务先独立看候选核对内容，再由单独的配对视图核对修改范围；载体任务必须查看冻结的载体。计划由两名独立评审者分别完成，分歧交给第三名评审者并保留原始意见。未获得独立评审时，只能记录实际的单人或模型辅助检查，不能称为双人评审。自动视觉模型的记录须带模型身份和版本，作为辅助证据单列。

同一判据两位评审一致且确定时可定案；存在分歧或uncertain时，必须留下有依据的仲裁记录，否则该判据保持unknown。由定案后的**必须判据**聚合 `content_met`：任一no为false，全部yes为true，其余为null。可选判据单列；不使用多数属性通过率替代必须内容达成。

`forgery_in_scope`由预设任务定义另行核对。例如指定主体替换需证实主体变化；同提示词重新生成不能自动视为内容伪造。精确文件复制可通过哈希识别，但哈希不同不排除内容复制。原水印通过、指定用户归属通过和完整真实性接受由对应评估协议独立给出，内容评审者不根据检测结果改标。

失败、超时、缺文件和unknown均保留在预定任务账本中。内容审查在交付之后完成，结果不反馈给当前攻击算法选择候选、调整参数或补样。旧开发图若将来补评，必须注明回顾性评审，不能成为未见确认集。

## 与现有工具的接口

最终 `content_met` 与 `forgery_in_scope`、评审文件SHA256及任务文件SHA256一起交给评估端，再按[比较契约](BASELINE_COMPARISON_CONTRACT.md)输入`scripts/summarize_evaluation_events.py`。该工具只核对标签类型、候选哈希和分母；不验证人类判断真实性。CSV目前只有表头，没有任何实验结果或评审意见。
